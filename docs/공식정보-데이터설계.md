# Navi 공식 정보 데이터 설계

## 원칙

사용자에게 노출되는 안내는 검토 완료된 공식 정보 레코드에 연결되어야 한다. 검색 모델은 후보를 찾는 데 사용할 수 있지만, 최종 답변의 근거는 이 데이터 저장소에서 가져온다.

## 핵심 엔터티

| 엔터티 | 용도 | 필수 필드 |
| --- | --- | --- |
| Source | 공식 원문 출처 | source_id, 기관명, URL, 문서명, 발행일, 접근일 |
| Program | 제도·서비스 기본 정보 | program_id, 명칭, 요약, 대상 분야, 적용 지역, 상태 |
| Guidance | 사용자 안내 단위 | guidance_id, program_id, 쉬운 말 안내, 준비사항, 담당자 확인 항목 |
| EligibilityNote | 자격 관련 일반 안내 | 조건 설명, 확정 금지 문구, 확인 주체 |
| Office | 신청·상담 기관 정보 | office_id, 기관명, 주소, 창구, 운영 시간, 연결 방식 |
| Review | 정보 검토 이력 | reviewer, 검토일, 다음 검토일, 변경 사유, 승인 상태 |

## Program 최소 스키마

```json
{
  "program_id": "welfare-elder-care-001",
  "name": "제도 공식명",
  "plain_name": "어르신 돌봄 관련 상담",
  "category": "elder-care",
  "region_scope": "national | local",
  "summary_easy": "일상생활에 도움이 필요한 어르신이 상담할 수 있는 서비스입니다.",
  "preparation_items": [
    { "label": "신분증", "status": "basic", "needs_confirmation": false }
  ],
  "individual_confirmation_items": ["가구 상황", "소득과 재산 기준"],
  "source_ids": ["source-001"],
  "review_status": "approved",
  "reviewed_at": "2026-08-29",
  "next_review_at": "2026-11-29"
}
```

## 정보 상태

| 상태 | 의미 | 사용자 노출 |
| --- | --- | --- |
| draft | 수집했지만 검토 전 | 노출 금지 |
| approved | 담당자가 검토·승인함 | 노출 가능 |
| review_required | 갱신 기한 경과 또는 원문 변경 의심 | 기본 노출 금지, 담당자 확인으로 전환 |
| retired | 종료 또는 대체됨 | 노출 금지 |

## 콘텐츠 작성 규칙

- `summary_easy`는 한 문장에 하나의 의미만 담는다.
- 준비 서류는 `기본 준비`, `해당할 때 준비`, `담당자 확인`으로 나눈다.
- 각 안내에는 적용 지역과 정보 기준일을 표시한다.
- 지자체 사업은 전국 공통 제도와 별도 레코드로 저장한다.
- 원문 URL만 저장하지 말고 문서 제목·발행기관·확인일을 함께 저장한다.

## 갱신 운영

- 모든 승인 정보에 다음 검토일을 설정한다.
- 원문 URL 오류, 사용자 신고, 담당자 정정은 즉시 `review_required`로 전환한다.
- 변경 승인 전에는 이전 정보를 계속 단정적으로 안내하지 않는다.
