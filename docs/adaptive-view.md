# Active User 시점 적응형 화면

키오스크 첫 화면에서 카메라를 자동으로 시작합니다. 로컬 [MediaPipe Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js) 모델(`frontend/public/models/face_landmarker.task`)이 얼굴의 눈 위치와 고개 상하 각도를 추정합니다. 손동작 입력을 켜면 얼굴·손 모델이 카메라 스트림 하나를 공유합니다. 탭이 숨겨지면 얼굴 추적을 중지합니다. 영상과 추적 ID는 저장하거나 서버로 보내지 않으며, 얼굴을 신원 확인에 사용하지 않습니다.

카메라 권한 거부·오류 또는 유효한 보정값이 없는 경우 기본 `MID` 배치를 유지합니다. 터치·음성·직접 입력은 계속 사용할 수 있습니다.

## 관리자 보정

시연에 사용할 iPad에서 **실제로 사용할 브라우저와 주소**로 `/admin`에 로그인한 뒤 **이 기기의 시점 높이 보정 > 카메라 보정 시작**을 누릅니다. 관리자 화면에 실시간 영상, 얼굴 테두리, 눈높이 선, 눈 위치 Y값과 고개 상하 각도가 표시됩니다. 한 사람만 화면에 보이도록 하고 `HIGH`, `MID`, `LOW`를 차례로 측정합니다. 높은·일반 시점에서는 자연스럽게 화면을 보고, 낮은 시점에서는 앉아서 화면을 올려다봅니다. 각 자세를 약 1초간 안정적으로 유지한 뒤 측정 버튼을 누릅니다.

측정은 최근 900ms의 표본을 사용하며, 최소 5개 표본과 눈 위치·고개 각도의 안정성이 필요합니다. 저장 시 눈 위치는 `HIGH < MID < LOW` 순서로 충분히 떨어져 있어야 하고, `LOW`와 `MID` 고개 각도도 구별되어야 합니다. 조건을 충족하지 못하면 안내에 따라 다시 측정합니다. 저장하거나 취소하면 관리자 카메라 미리보기가 종료됩니다.

보정값은 영상이 아니라 숫자 기준값이며, 이 브라우저의 `localStorage`에만 저장됩니다. 브라우저를 닫거나 iPad를 재부팅해도 보통 유지되지만, 다른 기기·브라우저·접속 주소로 옮겨지지 않습니다. 사이트 데이터 삭제, 시크릿 모드 종료, 카메라 설치 각도 변경 시 다시 보정해야 합니다. 이전 얼굴 모델에서 만든 눈높이 전용 보정값은 읽을 수 있지만, 현재 모델과 기준점이 다를 수 있으므로 새로 측정하는 것이 좋습니다.

## 자동 판정

눈 위치 Y는 영상 위쪽이 0, 아래쪽이 1입니다. `HIGH/MID`, `MID/LOW` 경계는 관리자에게 저장된 인접 기준값의 중간점입니다. 새 Active User를 확인한 뒤 같은 후보 판정이 약 800ms 유지되어야 화면을 바꿉니다.

- 눈 위치가 낮고 고개를 올려다보는 각도도 보정된 `LOW` 방향이면 `LOW`로 판정합니다. 눈 위치가 `MID/LOW` 경계의 바로 위에 있어도 두 신호가 일치하면 `LOW` 후보로 인정합니다.
- 눈 위치가 충분히 낮으면 고개 각도가 중립이어도 `LOW`로 판정할 수 있습니다. 반대로 낮은 눈 위치와 명백히 반대되는 각도가 함께 감지되면 기존 배치를 유지합니다.
- 눈 위치와 각도가 엇갈리거나 경계 구간의 근거가 부족하면 기존 배치를 유지합니다. 고개 각도만으로 휠체어 이용 여부를 판단하지 않습니다.
- 고개 각도 보정이 없는 이전 저장값은 눈 위치만으로 판정합니다. 보정값이 전혀 없으면 자동 `HIGH/LOW` 판정 없이 `MID`를 유지합니다.

이 규칙의 임계값은 시연용 초기값입니다. 거리·조명·카메라 각도·자세에 따라 결과가 달라질 수 있으므로 실제 iPad에서 검증해야 합니다. 일반 사용자는 **음성 설정 > 조작 버튼 높이**에서 수동으로 `LOW/MID/HIGH`를 선택할 수 있습니다. 수동 선택 중 자동 판정은 화면에 적용되지 않으며, 새 상담을 시작하면 자동 모드로 돌아갑니다.

## 디버그 화면

첫 화면의 **카메라 디버그 보기**를 누르면 영상과 현재 조작자 얼굴 테두리, 카메라 판정, 실제 화면 배치, 눈 위치 Y, 보정 경계, 고개 각도 및 판정 근거가 표시됩니다. `카메라 판정`과 `현재 화면`은 수동 배치 중 서로 다를 수 있습니다. 얼굴이 감지되지 않으면 얼굴 수와 측정 대기 상태를 확인합니다. 보정값이 없으면 자동 분류가 불가능하다는 안내와 관리자 보정 링크가 표시됩니다. 디버그 창은 닫을 수 있으며 영상은 저장되지 않습니다.

## 사용자 전환

얼굴의 위치·크기·추적 연속성을 기반으로 Active User를 유지합니다. 기존 얼굴 추적이 끊긴 상태에서 새 얼굴이 약 400ms 안정적으로 나타나거나, 기존 얼굴이 남아 있어도 다른 얼굴이 주요 위치를 더 오래 점유하면 전환합니다. 한 프레임 누락이나 자세 변화만으로 전환하지 않습니다.

상담 중 사용자가 바뀐 것으로 판단되면 **계속 사용 / 새로 시작** 안내를 표시합니다. 녹음·응답 처리·영상 안내 중에는 자동 초기화 시간을 세지 않습니다. 다른 사용자가 계속 감지되고 8초 동안 응답이 없으면 이전 상담을 화면에서 지웁니다. 이미 발급된 QR 요약 링크나 서버 기록은 이 화면 초기화로 삭제되지 않습니다.

## 검증

`frontend`에서 `node --experimental-strip-types --test tests/*.test.mjs`, `npx playwright test --config=playwright.touchless.config.ts`, `npm run build -- --logLevel silent`를 실행합니다. 자동 테스트는 합성 얼굴 프레임과 가짜 카메라를 사용하므로 실제 사람의 각도 분류 정확도를 보증하지 않습니다. 실제 iPad에서 보정·조명·두 사람 동시 등장·휠체어 높이·얼굴/손 모델 동시 실행 성능을 따로 확인해야 합니다.
