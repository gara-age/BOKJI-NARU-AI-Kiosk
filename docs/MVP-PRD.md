# Navi 민원 준비 도우미 MVP PRD

## 1. 목적

Navi는 주민센터와 복지관 방문자가 자신의 상황을 음성 또는 터치로 설명하면, 공식 행정·복지 정보를 바탕으로 상담 준비사항을 쉬운 말로 안내하고 담당자 상담으로 연결하는 접근성 서비스다.

MVP의 목표는 신청 자격을 판정하거나 신청을 자동 처리하는 것이 아니다. 이용자의 재방문과 서류 누락을 줄이고, 담당자가 기본 안내보다 개별 판단이 필요한 상담에 집중하도록 돕는 것이다.

## 2. MVP 범위

### 도입 환경

- 파일럿 기관: 주민센터 또는 복지관 1곳
- 입력 방식: 음성 입력과 대형 터치 UI
- 출력 방식: 화면 안내, TTS, QR 코드, 선택적 인쇄
- 담당자 연결: 담당 창구/위치 안내와 상담 요약 QR 제공

### 우선 지원 분야

각 기관의 실제 안내 자료로 세부 민원을 확정한다. 전국 공통 제도와 지자체 고유 사업은 반드시 구분해서 관리한다.

| 분야 | MVP에서 다룰 대표 질문 |
| --- | --- |
| 생활 지원 | 생활이 어려울 때 받을 수 있는 도움, 긴급 지원 문의 |
| 어르신 지원 | 돌봄, 식사, 일상생활 지원 문의 |
| 장애인 지원 | 복지 서비스, 활동 지원, 편의 지원 문의 |
| 청년 주거 | 월세, 주거, 자립 지원 문의 |
| 아동·가족 | 한부모, 양육, 돌봄 지원 문의 |

### MVP 제외 범위

- 수급·지원 자격의 자동 판정
- 지원 금액, 승인 가능성, 처리 기간의 확정 안내
- 신청서 자동 제출 및 민감정보 자동 입력
- 법률·의료 판단
- 기관 시스템 미연동 상태의 번호표 자동 발급
- 열린 웹 검색 결과를 근거 없이 답변에 사용하는 기능

## 3. 사용자와 역할

| 역할 | 목적 | 주요 행동 |
| --- | --- | --- |
| 민원인 | 필요한 상담을 준비한다 | 상황 설명, 추가 질문 응답, 결과 확인, QR/출력 수령 |
| 담당자 | 개별 판단과 실제 신청을 처리한다 | 상담 요약 확인, 추가 서류 확인, 최종 안내 |
| 기관 관리자 | 정보와 운영 품질을 관리한다 | 공식 정보 검토, 창구 정보 수정, 로그·KPI 확인 |

## 4. 핵심 사용자 흐름

1. 이용자가 `무엇을 도와드릴까요?` 화면에서 음성 또는 터치 입력을 선택한다.
2. Navi가 상황을 짧게 받아 적고, 이용자가 내용이 맞는지 확인한다.
3. 부족한 정보만 1~3개의 쉬운 질문으로 확인한다. 예: 연령대, 가구 상황, 거주 지역, 원하는 도움의 종류.
4. Navi가 관련 제도 또는 상담 분야를 최대 3개까지 제안한다.
5. 각 결과에 기본 안내, 준비할 수 있는 서류, 신청·상담 기관, 공식 출처, 정보 확인일, 상태를 표시하고 읽어 준다.
6. 개인 상황에 따라 달라지는 항목은 `담당자 확인 필요`로 분리한다.
7. 이용자는 QR 코드, 인쇄물 또는 화면으로 상담 요약을 받는다.
8. Navi가 담당 창구와 다음 행동을 안내한다. 기관 연동 시 상담 요약을 담당자가 열 수 있다.

## 5. 기능 요구사항

| ID | 기능 | MVP 요구사항 | 완료 기준 |
| --- | --- | --- | --- |
| FR-01 | 입력 | 음성과 터치 입력을 제공한다 | 두 입력 방식으로 상담 흐름을 완료할 수 있다 |
| FR-02 | STT 확인 | 음성 인식 결과를 화면에 표시하고 수정·재입력을 지원한다 | 확인 전에는 다음 단계로 진행하지 않는다 |
| FR-03 | 의도 분류 | 지원 분야, 핵심 상황, 추가 확인 필요 항목을 추출한다 | 지원 분야 또는 담당자 연결 중 하나를 제시한다 |
| FR-04 | 추가 질문 | 한 번에 하나의 질문만, 최대 3개 질문한다 | 질문을 건너뛰거나 담당자 연결을 선택할 수 있다 |
| FR-05 | 공식 정보 검색 | 검증된 기관 정보만 검색 대상으로 사용한다 | 모든 결과에 출처와 확인일이 있다 |
| FR-06 | 쉬운 말 안내 | 행정 용어를 쉬운 문장으로 요약한다 | 자격 확정 표현을 사용하지 않는다 |
| FR-07 | 준비사항 | 기본 서류, 신청·상담처, 추가 확인 항목을 나눈다 | 서류마다 `기관 확인 필요` 여부가 표시된다 |
| FR-08 | 근거 표시 | 출처명, 원문 링크/문서, 정보 확인일, 상태를 표시한다 | 근거 없는 결과는 사용자에게 노출하지 않는다 |
| FR-09 | 상담 요약 | 이용자 설명, 탐색 분야, 결과, 확인 필요 항목을 요약한다 | QR 또는 인쇄물로 전달할 수 있다 |
| FR-10 | 담당자 연결 | 창구명, 위치, 운영 시간 또는 호출 방법을 안내한다 | 연결 정보가 없으면 직원 도움 요청을 제시한다 |
| FR-11 | 접근성 | 큰 글씨, 고대비, TTS 반복, 느린 읽기, 큰 터치 영역을 지원한다 | 키보드 없이 핵심 흐름을 완료할 수 있다 |

## 6. 결과 상태와 문구 규칙

| 상태 | 사용 조건 | 사용자 표시 예시 |
| --- | --- | --- |
| 확인됨 | 공식 원문에서 직접 확인한 일반 정보 | `복지로에서 신청 방법을 확인했습니다.` |
| 일부 확인됨 | 기본 정보는 확인했으나 개인 조건에 따라 달라짐 | `가구의 소득과 재산은 상담에서 확인이 필요합니다.` |
| 담당자 확인 필요 | 최종 판단, 예외, 민감정보 확인이 필요한 경우 | `담당자와 함께 대상 여부를 확인해 주세요.` |

금지 표현: `받을 수 있습니다`, `자격이 됩니다`, `승인됩니다`, `지원금은 얼마입니다`처럼 개인 결과를 확정하는 문장.

권장 표현: `대상일 수 있습니다`, `기본 요건을 확인해 볼 수 있습니다`, `실제 대상 여부는 담당자가 확인합니다`.

## 7. 비기능 요구사항

- 응답 목표: 정보 검색 결과는 10초 이내, 음성 안내 시작은 3초 이내를 목표로 한다.
- 장애 대응: STT·검색 실패 시 재시도와 직원 호출 경로를 제공한다.
- 감사 가능성: 사용자에게 제시한 결과의 출처, 버전, 확인 시점, 정책 판정 기록을 남긴다.
- 정보 최신성: 만료일 또는 검토 주기가 지난 데이터는 자동으로 `검토 필요` 상태로 전환한다.
- 언어: 1차는 한국어만 지원하며, 다국어는 별도 범위로 관리한다.

## 8. 성공 지표

| 지표 | 정의 | 파일럿 측정 방식 |
| --- | --- | --- |
| 상담 준비 완료율 | QR/출력 또는 창구 안내까지 완료한 세션 비율 | 세션 이벤트 |
| 담당자 개입률 | 기본 안내 중 직원 도움을 요청한 세션 비율 | 도움 요청 이벤트 |
| 서류 누락률 | 상담 후 추가 서류 때문에 재방문한 비율 | 담당자 기록, 표본 조사 |
| 안내 이해도 | 안내 후 `이해했어요` 응답 비율 | 1문항 설문 |
| 공식 정보 근거율 | 근거가 연결된 답변 비율 | 응답 감사 로그 |
| 평균 완료 시간 | 시작부터 상담 요약 발급까지 걸린 시간 | 세션 이벤트 |

## 9. 수용 기준

- 이용자는 제도명을 모르는 상태에서도 하나의 상담 분야와 다음 행동을 안내받는다.
- 결과마다 최소 1개의 승인된 공식 출처와 정보 확인일이 표시된다.
- 개인 자격, 금액, 승인을 확정하는 문구가 결과에 포함되지 않는다.
- 불확실하거나 정보가 없는 경우 담당자 연결을 우선 제시한다.
- 음성 없이 터치만으로, 또는 터치 없이 음성 중심으로 핵심 흐름을 진행할 수 있다.
