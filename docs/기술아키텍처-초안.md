# Navi 기술 아키텍처 초안

## 확정된 MVP 전제

- 대상: 주민센터 방문 민원인
- 상담 분야: 기초생활 지원, 긴급복지, 노인 돌봄, 장애인 활동 지원, 청년 월세
- 채널: 마이크·스피커가 있는 태블릿 또는 모니터 기반 웹 키오스크
- 인터페이스: 음성 대화, 터치 조작, MuseTalk 기반 디지털 휴먼
- 결과 전달: QR 코드, 선택적 출력, 사용자 동의 후 문자·이메일, 담당자 관리자 화면
- 기관 연동: 1차 데모에서는 실제 주민센터 시스템과 연동하지 않음
- 정보: 공공 정보 API와 승인된 초기 데이터로 조회

## 권장 구성

```text
[웹 키오스크]
  마이크 / 터치 / 화면 / 스피커 / 인쇄 요청
        |
        +-- STT --> [대화·상담 API] --> [공식 정보 저장소]
        |                  |                    |
        |                  +--> [정책 검증] <----+
        |                  |
        |                  +--> [상담 요약·QR API] --> [관리자 화면]
        |
        +-- TTS 오디오 --> [MuseTalk 영상 서비스] --> 디지털 휴먼 영상

[선택적 전달 서비스]
  사용자 동의 확인 --> 문자 또는 이메일 발송
```

## 구성 요소별 책임

| 구성 요소 | 책임 | 구현 유의점 |
| --- | --- | --- |
| 키오스크 웹 | 음성·터치 입력, 쉬운 말 결과, QR·인쇄 UI, 접근성 | 세로형과 가로형 화면 모두에서 동작하도록 반응형으로 구현 |
| 대화·상담 API | 의도 분류, 추가 질문, 상담 흐름 상태 관리 | 개인 자격 판정 대신 상담 분야와 확인 항목만 생성 |
| 정보 조회 계층 | 공공 API 호출, 캐시, 승인 데이터 검색 | API 원문·조회일·지역을 결과 근거와 함께 보관 |
| 정책 검증기 | 출처·상태·금지 문구·담당자 전환 검사 | 검증에 실패하면 답변 대신 담당자 연결 |
| TTS | 쉬운 말 안내를 한국어 음성으로 생성 | 텍스트와 오디오를 분리해 장애 시에도 화면 안내 유지 |
| MuseTalk 서비스 | TTS 오디오와 준비된 휴먼 영상을 립싱크 | GPU 워커로 분리하고, 지연 시 정지 영상 또는 음성 모드로 전환 |
| 관리자 화면 | 상담 요약 조회, 공식 정보 검토, 통계 | 역할 기반 접근 권한과 세션 만료 적용 |
| 전달 서비스 | QR 생성, 인쇄용 문서, 문자·이메일 발송 | 연락처 입력과 발송 전 명시적 동의를 받음 |

## MuseTalk 적용 원칙

- MuseTalk은 TTS가 만든 오디오에 맞춰 준비된 디지털 휴먼 영상의 입 모양을 합성하는 서비스로 사용한다.
- 웹 브라우저에서 직접 실행하지 않고, GPU가 있는 별도 서비스에서 실행한다.
- 각 안내 문장을 짧은 오디오 단위로 처리한다. 합성 지연이 길면 음성·자막을 먼저 출력하고 영상은 대체 상태로 표시한다.
- 데모용 휴먼은 모델·배우의 초상 사용 동의와 상업적 사용 가능 여부가 확인된 원본만 사용한다.
- 영상 합성 장애는 민원 안내 전체의 장애가 아니어야 한다. 디지털 휴먼 없이도 음성·텍스트·터치 흐름이 작동해야 한다.

MuseTalk의 공식 저장소는 Python, CUDA, FFmpeg 기반 환경과 실시간 추론 경로를 안내하며, 1.5 버전 사용을 권장한다. 실시간 성능은 GPU 사양·아바타 준비·영상 품질에 따라 달라지므로, 실제 장비에서 첫 문장 시작 지연과 프레임 안정성을 별도 측정한다. [MuseTalk 공식 저장소](https://github.com/TMElyralab/MuseTalk)

## 개인정보 데이터 흐름

| 데이터 | 사용 목적 | 기본 저장 원칙 |
| --- | --- | --- |
| 나이·성별 | 상담 분야를 좁히기 위한 추가 질문 | 상담 세션 종료 후 삭제 또는 비식별 통계만 보관 |
| 사용자 질의 | 상담 요약과 정보 탐색 | 주민등록번호 등 탐지 즉시 마스킹, 원문 장기 보관 금지 |

| 음성 원본 | STT 처리 | 기본 미저장 |
| 상담 요약 | QR·출력·담당자 전달 | 만료 시간과 접근 토큰을 적용 |

## 데모 단계의 외부 연동

| 기능 | 데모 구현 | 파일럿 이후 전환 |
| --- | --- | --- |
| 공공 정보 조회 | 선택된 공공 API + 관리자 승인 레코드 | 기관·지자체별 정보 소스 확대 |
| 담당자 전달 | 내부 관리자 화면의 상담 요약 목록 | 기관 인증·업무 시스템 연동 |
| QR | 만료되는 상담 요약 URL | 본인 확인·기관 인증 정책 적용 |
| 인쇄 | 브라우저 인쇄용 상담 준비서 | 키오스크 프린터 연동 |
| 문자·이메일 | 발송 화면과 동의 흐름, 실제 발송은 비활성 또는 테스트 수신처 제한 | 기관 승인 발신 수단과 개인정보 정책 확정 후 활성화 |

## 개발 순서

1. 반응형 키오스크와 관리자 화면의 정적 프로토타입을 구현한다.
2. 5개 민원 분야의 승인된 예시 데이터와 상담 흐름을 연결한다.
3. STT·TTS를 연결하고, 마이크와 스피커가 있는 실제 장비에서 접근성을 점검한다.
4. MuseTalk GPU 서비스를 연결하고 대체 음성 모드를 검증한다.
5. QR·인쇄·관리자 전달을 연결한다.
6. 공공 정보 API를 연결하고 출처·갱신·검토 흐름을 운영한다.
7. 기관 승인 뒤 문자·이메일 및 실제 업무 시스템 연동을 진행한다.

## 개발 시작 전 남은 결정

- 파일럿 대상 주민센터 또는 지자체
- 사용할 공공 정보 API와 각 API의 접근 권한·호출 한도
- 디지털 휴먼의 외형, 목소리, 초상 사용 권리
- 관리자 계정 수와 역할: 정보 검토자, 상담 담당자, 운영 관리자
- 문자·이메일 발송의 실제 도입 시점
- 상담 기록과 QR 요약의 보관 기간
